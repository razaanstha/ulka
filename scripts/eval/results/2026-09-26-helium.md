# Helium live verification, 2026-09-26

Tested the installed unpacked Ulka extension in the existing Helium profile through its real sidepanel, using the configured model. These results include model latency and live browser behavior. They are separate from scripted runtime fixtures and the synthetic streaming benchmark.

## Fixes supported by failures

- `extract_page` and `act_action` created a second debugger attachment while the task already owned one. Both now reuse the task session. Host-wiring regressions exercise the actual background worker and reject duplicate attachment.
- Planner compaction discarded replay action descriptors and extracted values. It now preserves extraction results and a bounded catalog of complete descriptors, including their fingerprints. Omitted actions are explicitly reported.
- Debugger collision messages now acknowledge that earlier actions may have completed.
- The failed overlay trace showed one Escape clearing occlusion, followed by two redundant Escapes before the cycle guard stopped the task. Escape now returns an unverified subgoal checkpoint to the planner after recording progress and enforcing existing shared cycle limits. A regression proves that repeated no-change Escapes across subgoals still stop.
- The live runtime resolved a cancelled `complete_task` normally. That caused a second full verification for action tasks and an `idle` status for already-satisfied tasks. Both resolved and thrown cancellation now retain verified completion without another verification call.
- Chrome sometimes rejects browser control when another extension's protected popup is present. This now stops immediately with the exact access limitation and a partial-progress warning instead of retrying three times and reporting generic service unavailability.
- Exhausted Jev gateway attempts from observation tools now stop the task just as action subgoals already did.
